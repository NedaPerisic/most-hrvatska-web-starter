Entity Mapping & GEO

Kako složiti web tako da nas AI tražilice (ChatGPT, Perplexity, Google AI Overviews, Copilot) razumiju kao jasan, povezan entitet — i citiraju MOST kao izvor odgovora.

Što je to, u jednoj rečenici

Umjesto da web bude „skup stranica s tekstom”, opisujemo stranku, zastupnike, teme i odbore kao stvari (entitete) — svaku s fiksnim identifikatorom i vezama na pouzdane izvore — pa AI motor može sa sigurnošću reći tko je MOST, tko su ljudi i za što se zalaže.

Dokaz iz prakse — Ghost Citation

7%

AI citata dolazi sa stranica koje nikad nisu bile u top-10 Google rezultata. AI ih je našao navigacijom kroz veze među entitetima, a ne preko pozicije u tražilici. Pozicija ≠ AI citat. Navigacijski graf je novi signal — i taj postotak raste.

TurboQuant — „pod” koji ne kontroliramo

Google je novim algoritmom (TurboQuant) AI-ju učinio ~4× jeftinijim da po jednom upitu istraži puno više izvora umjesto par. To znači da AI sad „šeta” kroz više stranica nego ikad. Ono što odlučuje hoćemo li biti među tim izvorima nije pozicija — nego dohvatljivost u grafu entiteta.

„TurboQuant je pod. Ne kontroliraš ga. Ono što kontroliraš je je li tvoj site mjesto kroz koje AI agent može hodati — ili slijepa ulica koju posjeti jednom i ode.” — Volpini, SEO Week 2026

Pojmovnik · brza referenca

Svi pojmovi na jednom mjestu, na ljudskom.

Entitet
„Stvar” s identitetom: osoba, organizacija, tema. Postoji i izvan stranice — nije samo riječ u tekstu.
Entity page (dom entiteta)
Stranica koja je službeni dom entiteta (npr. profil zastupnika). Sve ostalo se na nju poziva.
JSON-LD
Standardni format kojim entitet opisujemo strojevima. Sjedi nevidljivo u stranici.
Tag <script type="application/ld+json">
Mjesto u HTML <head>-u gdje taj opis živi. Posjetitelj ga ne vidi, crawler ga čita.
@id
Fiksni „matični broj” entiteta (jedan URL). Isti na svakoj stranici — tako stroj zna da je riječ o istoj osobi.
@graph
Popis više entiteta povezanih u jednu mrežu (stranka ↔ zastupnik ↔ tema).
sameAs
Veze na vanjske izvore (Wikipedia, Wikidata, Sabor.hr, službeni profili) koji potvrđuju da je entitet stvaran.
Wikidata / Q-ID
Javna baza znanja iza Googlea i AI-ja. Q-ID je jedinstveni broj entiteta — globalno „sidro”.
Graph reachability
Dohvatljivost: koliko je tvoj entitet povezan i lako dohvatljiv kad AI „šeta” grafom. Novi ključni signal.
IndexNow
Besplatni protokol koji Bingu i partnerima javi čim nešto objaviš/promijeniš. Najjači taktički potez za svježinu.
Crawler
Program AI-ja/tražilice koji posjeti stranicu i pročita sadržaj i tagove.
GEO
Generative Engine Optimization — optimizacija da te AI citira, za razliku od SEO-a (da te Google rangira).

Entity page — gdje to živi na stranici

Da, točno — na strani to izgleda kao tag. Ista stranica ima dva lica: ono što vidi posjetitelj, i nevidljivi <script> blok koji čita AI.

Što vidi posjetitelj
most.hr/clanovi/nikola-grmoja

Nikola Grmoja

Predsjednik Kluba zastupnika

Saborski zastupnik MOST-a. Biografija, područja rada, aktivnosti u Saboru…

Što čita AI — isti URL, nevidljivi tag
<head> · izvor stranice
<script type="application/ld+json"> { "@type": "Person", "@id": ".../nikola-grmoja#person", "name": "Nikola Grmoja", "memberOf": "MOST", "sameAs": [ "wikipedia…", "sabor.hr…" ] } </script>

Bit: dizajn stranice se ne mijenja — samo se u kod doda taj nevidljivi tag. Jedna stranica = jedan entitet = jedan tag.

Mreža entiteta (knowledge graph)

Svaki entitet ima fiksni @id i povezan je s ostalima. Ovo je „mapa” koju gradimo kroz tagove.

stranka zastupnik tema vanjski izvor memberOf / about sameAs
Ključ: isti @id se kroz cijeli site uvijek referencira, nikad se ne redefinira. Tako sve stranice grade jedan povezan graf, a ne 50 odvojenih opisa.

Kako tag izgleda u kodu

Srce stvari — stranka i zastupnik povezani u jedan @graph, sa sameAs na vanjske izvore.

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "PoliticalParty",
      "@id": "https://most.hr/#organizacija",
      "name": "MOST",
      "url": "https://most.hr",
      "sameAs": [
        "https://hr.wikipedia.org/wiki/Most_(stranka)",
        "https://www.wikidata.org/wiki/Q######",
        "https://www.facebook.com/MostHrvatska"
      ]
    },
    {
      "@type": "Person",
      "@id": "https://most.hr/clanovi/nikola-grmoja#person",
      "name": "Nikola Grmoja",
      "jobTitle": "Predsjednik Kluba zastupnika",
      // veza na stranku gore — isti @id
      "memberOf": { "@id": "https://most.hr/#organizacija" },
      "sameAs": [
        "https://hr.wikipedia.org/wiki/Nikola_Grmoja",
        "https://www.wikidata.org/wiki/Q######",
        "https://www.sabor.hr/hr/zastupnici/nikola-grmoja"
      ]
    }
  ]
}
</script>

Implementacija & automatizacija

Najvažnije pitanje: kako da se tag sam generira kad dodamo novog zastupnika ili vijest? Odgovor: schema se napiše jednom, a postojeći template radi ostalo.

Princip: napiši jednom → vrijedi za sve

Web već ima [slug].astro predložak koji automatski radi stranicu za svakog zastupnika i svaku vijest. Automatizacija = u taj predložak dodamo jednu schema komponentu. Od tada svaki novi unos sam dobije i svoj entity tag — s ispravnim @id i vezom na stranku. Nitko ne dira kod ni JSON ručno.

Kako to izgleda u kodu — 3 dijela

Ilustrativno (Astro). Schema logika je u koraku 2 — napisana jednom, koristi se za sve.

// 1) PODACI — u Sanity CMS-u. PR popuni polja u Sanity Studiju.
//    Sanity schema: zastupnik { name, role, slug, sameAs[] }
{
  name: "Nikola Grmoja",
  role: "Predsjednik Kluba zastupnika",
  sameAs: [ "https://hr.wikipedia.org/wiki/Nikola_Grmoja",   // ← linkove daje PR
            "https://www.sabor.hr/.../nikola-grmoja" ]
}


// 2) KOMPONENTA — schema napisana JEDNOM, vrijedi za svakog
//    src/components/PersonSchema.astro
const { entry } = Astro.props;
const schema = {
  "@type": "Person",
  "@id": `https://most.hr/clanovi/${entry.slug}#person`,  // @id iz slug-a
  "name": entry.data.name,
  "jobTitle": entry.data.role,
  "memberOf": { "@id": "https://most.hr/#organizacija" },  // veza na stranku
  "sameAs": entry.data.sameAs
};
<script type="application/ld+json" set:html={JSON.stringify(schema)} />


// 3) TEMPLATE — vrti se za SVE zastupnike automatski
//    src/pages/clanovi/[slug].astro   (već postoji!)
const clanovi = await sanityClient.fetch(`*[_type == "zastupnik"]`);  // povuče iz Sanityja
// → svaki unos dobije svoju stranicu
<PersonSchema entry={entry} />   // ← tag se sam ubaci
<article>…vidljivi sadržaj…</article>
Vijesti idu isto: NewsArticle komponenta s author → poveže se na @id postojećeg zastupnika. Tako svaka nova vijest automatski „zakači" u graf (vijest → autor → stranka → tema).

PR ekipa dodaje bez koda — preko Sanityja

Sanity CMS

PR uređuje zastupnike i vijesti u Sanity Studiju — popuni polja (ime, uloga, sameAs linkovi), ne dira kod.

Webhook → deploy

Objava u Sanityju okine Vercel deploy hook — site se sam osvježi za ~minutu.

IndexNow

Mali post-build skript javi Bingu/partnerima nove URL-ove — AI brže vidi promjenu.
